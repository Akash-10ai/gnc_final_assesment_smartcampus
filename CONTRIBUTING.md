# Contributing to Smart Campus Management System

Thank you for your interest in contributing to this project! This document provides guidelines and instructions for contributing.

## 📋 Code of Conduct

- Be respectful and professional in all interactions
- Report bugs and issues responsibly
- Provide constructive feedback
- Follow Java coding standards and best practices

## 🐛 Reporting Bugs

Before creating a bug report, check the existing issues as you might find out that you don't need to create one.

**When filing a bug report, include:**
- Clear and descriptive title
- Detailed description of the problem
- Steps to reproduce the issue
- Expected vs actual behavior
- Your environment details (Java version, OS, IDE)
- Screenshots or error logs if applicable

## 🎯 Suggesting Enhancements

Enhancement suggestions are welcome! When suggesting enhancements:
- Use a clear and descriptive title
- Provide a detailed description
- List potential use cases
- Explain why this enhancement would be useful

## 📝 Pull Request Guidelines

1. **Fork the repository** and create a new branch for your feature/fix
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. **Follow Java coding standards:**
   - Use meaningful variable and method names
   - Add Javadoc comments for public classes and methods
   - Keep methods focused and concise (single responsibility)
   - Use proper exception handling

3. **Commit messages should be clear:**
   ```
   fix: Correct null pointer exception in Student class
   feat: Add student search functionality
   docs: Update README with new features
   refactor: Improve code organization
   ```

4. **Add tests for your changes** (if applicable)
   - Test normal cases
   - Test edge cases
   - Test error conditions

5. **Update documentation:**
   - Update README if features are added/changed
   - Update code comments
   - Add examples if needed

6. **Submit your pull request:**
   - Provide a clear description of changes
   - Reference any related issues
   - Ensure all tests pass
   - Request review from maintainers

## 🧪 Testing Guidelines

- Write unit tests for new features
- Ensure existing tests continue to pass
- Test with various inputs (valid, invalid, edge cases)
- Test with different Java versions (8+)

## 📚 Documentation Standards

- Use clear and concise language
- Include code examples where helpful
- Update the README for user-facing changes
- Add comments for complex logic
- Use Javadoc for all public APIs

## 🔍 Code Review Process

All submissions require review before merging:
- At least one maintainer review
- Code must pass automated checks
- No merge conflicts
- Documentation is complete
